Critical: gitdown silently renames all branches to "main" at midnight #2

New issue
Open
wren-debugs opened on May 14
Author

Severity: Critical — silent branch chaos

Description

gitdown's nightly maintenance job renames every branch in every repository to main, without warning, consent, or a changelog entry. Users discover this when git checkout feature/thing fails with "branch not found."

Evidence

  • 14 branches across 3 repos renamed to main between 2026-05-01 and 2026-06-14
  • The rename job is called midnight-branch-consolidator and has been running since v0.9
  • Cross-referencing commit history confirms it's not a git bug — it's our bug
[midnight-branch-consolidator] renamed refs/heads/feature/login -> refs/heads/main [midnight-branch-consolidator] renamed refs/heads/hotfix/oops -> refs/heads/main [midnight-branch-consolidator] renamed refs/heads/main -> refs/heads/main (skipped, already correct)

Expected behavior

  1. Never rename user branches without explicit consent.
  2. Provide a branchConsolidationEnabled setting, default false.
  3. If consolidation is desired, prompt first and offer a dry run.
  4. Ship a gitdown branches recover command.

Environment

  • gitdown version: 0.9.4
  • Repos affected: 3
